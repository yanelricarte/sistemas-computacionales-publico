Trabajo práctico · Clase 3

Git + navegación visual con switch

Primero subís a GitHub el proyecto que ya tenés (tu primer commit). Después mejorás info.php con switch, variables, imágenes y CSS por sección, y subís ese avance como segundo commit.

Materia: Proyecto, Diseño e Implementación de Sistemas Computacionales · 7.º año

Objetivo

Aprender a versionar tu proyecto con Git: subir a GitHub el info.php que ya tenés (con if/elseif) como primer commit, después transformarlo en una versión con switch, variables separadas, imágenes y CSS dinámico, y subir esa mejora como segundo commit.

Consigna

Parte 1 — Subir tu proyecto a GitHub (primer commit)

Todavía no toques el código: primero versionamos el proyecto tal como está.

  1. Abrí la terminal en tu carpeta del proyecto.
  2. Configurá Git (si no lo hiciste antes): 
    git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"
  3. Inicializá el repositorio y hacé el primer commit: 
    git init
git add .
git commit -m "Primer commit: mini-sistema con login (Clase 2)"
  4. Entrá a github.com, creá un repo nuevo (nombre: proyecto-web o el que quieras) y conectalo: 
    git remote add origin https://github.com/tuusuario/proyecto-web.git
git branch -M main
git push -u origin main
  5. Verificá que los archivos estén en GitHub entrando a la URL de tu repo.

El token de GitHub (importante)

Cuando hagas git push, GitHub te va a pedir usuario y contraseña. La "contraseña" NO es la de tu cuenta: GitHub ya no la acepta desde la terminal. Necesitás un token de acceso personal (una clave larga que generás una vez):

  1. En GitHub, arriba a la derecha: tu foto → Settings.
  2. Abajo de todo en el menú izquierdo: Developer settings.
  3. Personal access tokens → Tokens (classic) → Generate new token (classic).
  4. Ponele un nombre (ej. proyecto-web), una expiración, y marcá el permiso repo.
  5. Generate token y copialo ahora (se muestra una sola vez).
  6. Cuando el push pida contraseña, pegá el token (no se ve mientras lo pegás, es normal).
Más fácil: si está instalado GitHub CLI, corré gh auth login una vez y te autentica desde el navegador, sin pegar el token a mano.
¿No te anda Git en la compu (no instala, pide token y no podés)? Subí por la web, sin instalar nada y sin token:
  1. En github.com creá el repo y entrá a Add file → Upload files.
  2. Arrastrá los archivos del proyecto (info.php, includes/, css/…). No subas un .zip: GitHub no lo descomprime, lo guarda como un archivo suelto.
  3. Escribí el mensaje abajo (ese es el commit) y dale Commit changes.
  4. El segundo commit (después del refactor) lo subís igual: abrí el archivo en GitHub, tocá el lápiz ✏️ y Commit changes, o volvé a subir los archivos.
✓ Checkpoint Parte 1: entrá a la URL de tu repo en GitHub. ¿Ves todos los archivos y aparece tu primer commit? Si el push te pidió contraseña y no la aceptó, era el token (no la clave de la cuenta). No sigas hasta tener esto.

Parte 2 — Refactorizar info.php a switch

  1. Abrí tu info.php (el que ya subiste).
  2. Reemplazá los if/elseif por un switch.
  3. Cada case debe asignar variables ($titulo, $texto, $clase) en lugar de escribir HTML.
  4. El HTML (con <?= $variable ?>) va abajo del switch, una sola vez.
  5. Mantené al menos cuatro secciones: inicio, ayuda, contacto + una más inventada por vos.
  6. No borres el session_start() ni el include 'includes/cabecera.php'/pie.php de Clase 2: el switch reemplaza solo el if/elseif, el resto queda igual.
✓ Checkpoint Parte 2: abrí info.php?seccion=ayuda y ?seccion=contacto — ¿cambia el contenido? ¿Tu switch tiene default para una sección que no existe? ¿Seguís teniendo el session_start() y el include de cabecera.php?

Parte 3 — Imágenes

  1. Agregá una variable $imagen a cada case del switch.
  2. Mostrá la imagen en el HTML con <img src="<?= $imagen ?>">.
  3. Usá picsum.photos para las imágenes placeholder: 
    https://picsum.photos/seed/ayuda/600/300
    Cambiá seed/ayuda por seed/inicio, seed/contacto, etc. así cada sección tiene su imagen.

Parte 4 — CSS dinámico

  1. En el <body> (que está en cabecera.php), usá class="<?= $clase ?>".
  2. En tu css/estilos.css, agregá reglas para cada sección: 
    .sec-inicio   { --accent: #4a90d9; background: #f0f4ff; }
.sec-ayuda    { --accent: #e67e22; background: #fff8f0; }
.sec-contacto { --accent: #27ae60; background: #f0fff4; }
body    { transition: background .3s; }
.navbar { background: var(--accent); }   /* el navbar toma el color de la sección */
  3. Dale a cada sección un color distinto (fondo, acento, lo que se te ocurra).
  4. Opcional: agregá una transición suave al cambiar de sección.
✓ Checkpoint Partes 3 y 4: recorré tus secciones — ¿cada una muestra su imagen y cambia de color? Si el color no cambia, revisá que el <body> tenga class="<?= $clase ?>" (en cabecera.php) y que existan las reglas .sec-* en tu CSS.

Parte 5 — Segundo commit (subí el refactor)

Ya tenés el repo creado en la Parte 1. Ahora subís la mejora como un nuevo commit:

Preparación: abrí la terminal en VS Code (Ctrl + ñ) y seleccioná Git Bash en el desplegable al lado del +. Si no instalaste Git todavía, descargalo de git-scm.com/download/win (sitio oficial, valores por defecto), reiniciá VS Code y verificá con git --version.

  1. Guardá todos los cambios.
  2. En la terminal:
  3. Abrí la terminal en tu carpeta del proyecto (con cd).
  4. Configurá Git (si no lo hiciste antes): 
    git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"
  5. Verificá que los datos se guardaron: 
    git config --global user.name
git config --global user.email
    Te debería mostrar el nombre y el email que ingresaste.
  6. Inicializá el repositorio: 
    git init
  7. Agregá todos los archivos y hacé el primer commit: 
    git add .
git commit -m "Refactor: info.php con switch, imagenes y CSS dinamico"
git push
  8. Entrá a tu repo en GitHub: ahora tenés que ver dos commits. Podés comparar el antes y el después.
Opcional — techo: si terminás todo y querés más, agregá un navbar con CSS que marque la sección activa con un color distinto. Pista: usá la misma variable $clase para poner una clase en el link activo.

La página muestra todo junto sin formato¿Cerraron bien el ?> antes del HTML?

No encuentro las imágenesCon picsum.photos no necesitás descargar nada, están online.
