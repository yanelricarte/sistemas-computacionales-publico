1. Git: primeros pasos

Git es un sistema de control de versiones. Guarda el historial de cambios de tu proyecto y te permite volver atrás si algo sale mal. Hoy lo primero que hacemos es subir a GitHub el proyecto que ya tenés de Clase 2 — para no perder nada y aprender a versionar — y más tarde subimos las mejoras como un nuevo commit.

Git ≠ GitHub

Se confunden todo el tiempo, pero son cosas distintas:

GitGitHub
Qué esUn programa que instalás en tu compu.Un sitio web (en la nube).
Para quéLlevar el historial de versiones de tu proyecto.Guardar ese proyecto online y compartirlo.
Dónde viveEn tu máquina, sin internet.En los servidores de GitHub, necesita internet.
Ejemplogit commit (guardás una versión)git push sube esas versiones a tu cuenta

Analogía: Git es sacar fotos de tu proyecto en tu celular; GitHub es subirlas a la nube para tenerlas a salvo y mostrarlas. Podés usar Git sin GitHub (todo local), pero GitHub sin Git no tiene sentido. Y ojo: GitHub no es el único — también existen GitLab y Bitbucket, que hacen lo mismo.

Paso a paso

1. Configurar Git (la primera vez):

git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

2. Ir a la carpeta de tu proyecto y activar Git:

cd C:/xampp/htdocs/clase02/
git init

git init crea un repositorio vacío en esa carpeta. Se hace una sola vez por proyecto.

3. Agregar archivos y hacer el primer commit (el proyecto tal como está, todavía con if/elseif):

git add .
git commit -m "Primer commit: mini-sistema con login (Clase 2)"
  • git add . agrega todos los archivos de la carpeta al "escritorio" (staging).
  • git commit -m "mensaje" saca la foto. El mensaje describe qué cambió.

4. Crear un repositorio en GitHub y subir:

  1. Entrá a github.com e iniciá sesión.
  2. Botón verde "New repository" (arriba a la derecha).
  3. Nombre: proyecto-web (o el que quieras). Dejá todo lo demás como está.
  4. Copiá estas líneas y ejecutalas en tu terminal:
git remote add origin https://github.com/tuusuario/proyecto-web.git
git branch -M main
git push -u origin main

5. Verificá: entrá a github.com/tuusuario/proyecto-web — tenés que ver todos tus archivos.

El token: cómo autenticarte en el push

Cuando hacés git push, GitHub te pide usuario y contraseña. La "contraseña" NO es la de tu cuenta: GitHub ya no la acepta desde la terminal. Necesitás un token de acceso personal, una clave larga que generás una sola vez:

  1. En GitHub: tu foto (arriba a la derecha) → Settings.
  2. Abajo de todo en el menú izquierdo: Developer settings.
  3. Personal access tokens → Tokens (classic) → Generate new token (classic).
  4. Nombre (ej. proyecto-web), una expiración, y marcá el permiso repo.
  5. Generate token y copialo en el momento (se muestra una sola vez).
  6. Cuando el push pida contraseña, pegá el token. No se ve mientras lo pegás: es normal, dale Enter igual.
Más fácil: si tenés GitHub CLI, corré gh auth login una vez y te autenticás desde el navegador, sin pegar el token a mano. Y si la máquina no te deja instalar nada, podés subir los archivos por la web (Add file → Upload files), que no pide token.

Segundo commit (después de mejorar el código)

Una vez que refactorices info.php (lo que viene en las próximas secciones), guardás y repetís el ciclo para subir esa mejora:

git add .
git commit -m "Refactor: info.php con switch, imagenes y CSS dinamico"
git push

Cada commit es un punto de guardado. Si después algo se rompe, podés volver a cualquier commit anterior.

2. De if/elseif a switch

Ya usás if / elseif / else para decidir. Hoy sumamos switch: otra estructura selectiva, más ordenada cuando comparás una misma variable contra varios valores fijos. Arranquemos con un repaso activo.

Repaso rápido: variables y estructuras de control en PHP

Lo básico que ya viste y vas a usar acá:

  • Variables: empiezan con $ → $nombre = 'Ana';
  • Mostrar un valor: echo $nombre; o el atajo <?= $nombre ?>
  • Comparar: == (igual), != (distinto). Los textos van entre comillas.
  • Condicional: if (...) { } elseif (...) { } else { }
  • Valor por defecto: $s = $_GET['seccion'] ?? 'inicio'; → si no viene nada, usa 'inicio'.

Recuperación de contenido

Antes de avanzar, recuperá lo que ya sabés: llevá cada situación a la estructura que mejor le queda y tocá Verificar. Pista: if/elseif sirve para rangos o condiciones distintas; switch, para comparar una misma variable contra valores fijos.

Dos formas de usarla: arrastrá la tarjeta a una zona, o seleccionala (clic / Enter) y después tocá la zona (o Enter).

Mostrar el contenido según la sección: inicio, ayuda o contacto
Calcular la nota: ≥ 9 Excelente, ≥ 6 Aprobado, si no Desaprobado
Elegir el saludo según el día: lunes, martes, … domingo
Mostrar “Es mayor de edad” si la edad es ≥ 18

if / elseif

rangos o condiciones distintas

switch

una misma variable contra valores fijos

En la clase anterior armaste info.php con if y elseif para mostrar distinto contenido según el valor de $_GET['seccion']. Ese enfoque funciona, pero cuando tenés muchas secciones el código se vuelve difícil de leer.

Acá viene switch. Compará:

// Con if/elseif
$s = $_GET['seccion'] ?? 'inicio';

if ($s == 'inicio') {
    echo '<h2>Inicio</h2>';
} elseif ($s == 'ayuda') {
    echo '<h2>Ayuda</h2>';
} elseif ($s == 'contacto') {
    echo '<h2>Contacto</h2>';
} else {
    echo '<h2>404</h2>';
}
// Con switch
$s = $_GET['seccion'] ?? 'inicio';

switch ($s) {
    case 'inicio':
        echo '<h2>Inicio</h2>';
        break;
    case 'ayuda':
        echo '<h2>Ayuda</h2>';
        break;
    case 'contacto':
        echo '<h2>Contacto</h2>';
        break;
    default:
        echo '<h2>404</h2>';
}

Cómo funciona

  • switch evalúa la variable una sola vez y salta al case que coincide.
  • Cuando encuentra el case correcto, ejecuta el código hasta el break.
  • break sale del switch. Sin break, sigue ejecutando el siguiente case (se llama fall-through).
  • default es el "else" del switch: se ejecuta si ningún case coincide.

Visto como esquema, el switch procesa así:

switch ($s)evalúa la variable una vez
→
case que coincidesalta directo ahí
→
ejecuta hasta breaky sale del switch
→
defaultsi ningún case coincide

Fall-through: ¿qué es y para qué sirve?

Fall-through (en inglés, "caer a través") es lo que pasa cuando un case no tiene break: en vez de salir del switch, sigue ejecutando el case de abajo, y el siguiente, hasta que encuentra un break o termina el switch. La mayoría de las veces es un error (te olvidaste el break)… pero a veces se usa a propósito: cuando querés que dos valores compartan el mismo código.

switch ($rol) {
    case 'admin':
    case 'supervisor':
        echo 'Acceso completo';
        break;
    case 'editor':
        echo 'Puede editar contenidos';
        break;
    default:
        echo 'Acceso limitado';
}

Acá admin y supervisor hacen lo mismo porque el primer case no tiene break.

Cuidado: olvidar un break sin querer es el error más común con switch. Siempre revisá que cada case tenga su break (a menos que quieras fall-through a propósito).

3. Separando datos de la vista

Si escribís HTML adentro de cada case del switch, estás mezclando la lógica con la presentación. Para un par de secciones funciona, pero cuando el proyecto crezca se vuelve un desastre.

La idea es simple: el switch solo asigna valores a variables, y el HTML se escribe una sola vez abajo.

switchdecide la sección
→
variables$titulo · $texto · $clase
→
HTML (1 vez)<?= $titulo ?>

La lógica (qué sección es) queda en el switch; la presentación (cómo se ve), en el HTML de abajo. Cada cosa en su lugar.

<?php
$seccion = $_GET['seccion'] ?? 'inicio';

// Valores por defecto
$titulo = 'Inicio';
$texto  = 'Bienvenido al sistema.';
$clase  = 'sec-inicio';

switch ($seccion) {
    case 'ayuda':
        $titulo = 'Ayuda';
        $texto  = 'Encontrá instrucciones y respuestas.';
        $clase  = 'sec-ayuda';
        break;
    case 'contacto':
        $titulo = 'Contacto';
        $texto  = 'Escribinos por cualquier consulta.';
        $clase  = 'sec-contacto';
        break;
}
?>
<!DOCTYPE html>
<html>
<body class="<?= $clase ?>">
  <h1><?= $titulo ?></h1>
  <p><?= $texto ?></p>
</body>
</html>

¿Qué ganamos?

  • Legibilidad: el switch tiene solo asignaciones, es fácil de leer.
  • Mantenibilidad: si querés cambiar cómo se ve la página, tocás el HTML de abajo, no el switch.
  • Escalabilidad: agregar una sección nueva es copiar un case con sus variables. No tocar nada del HTML.
Recordá: <?= $variable ?> es la abreviatura de <?php echo $variable; ?>. Pinta el valor directamente.
En tu proyecto: el ejemplo de arriba muestra el <html> completo para que se entienda la idea, pero en tu info.php el <head> y el navbar ya viven en cabecera.php (lo armaste en Clase 2). No los dupliques: dejá el switch arriba, hacé include 'includes/cabecera.php' y escribí solo el contenido de la sección. El <body class="<?= $clase ?>"> va en cabecera.php. Mantené también el session_start() y la protección de la página.

4. Mostrando imágenes

El mismo patrón de variables sirve para imágenes. Agregá $imagen al switch y mostrala en el HTML:

// Adentro del switch
case 'ayuda':
    $titulo = 'Ayuda';
    $texto  = 'Instrucciones de uso del sistema.';
    $imagen = 'img/ayuda.jpg';
    $clase  = 'sec-ayuda';
    break;

// En el HTML
<img src="<?= $imagen ?>" alt="<?= $titulo ?>">

Imágenes placeholder para desarrollo

Si no tenés las imágenes todavía, usá picsum.photos para generar placeholders:

$imagen = 'https://picsum.photos/seed/ayuda/600/300';
//         ──────────────┬─────────┬────┬───┬───
//                      seed      tema ancho alto
//         misma seed → misma imagen siempre

El parámetro seed hace que la imagen sea siempre la misma para esa sección. Después las reemplazás por imágenes reales.

Importante: las imágenes de placeholder son para desarrollo. Cuando el proyecto esté listo, las imágenes deberían ser propias o libres de derechos.

5. CSS dinámico por sección

"CSS dinámico" no significa que el CSS cambie solo: el CSS es siempre el mismo. Lo que cambia es qué reglas se aplican, porque PHP le pone una clase distinta al <body> según la sección. Así, con un único archivo de estilos, cada sección se ve distinta (otro color, otro fondo) sin escribir páginas separadas.

La idea en dos partes: PHP decide la clase (ya la cargás en $clase dentro del switch) y el CSS reacciona a esa clase.

Primero, PHP pone la clase en el <body>:

<!-- PHP elige la clase -->
<body class="<?= $clase ?>">

Y en el CSS:

/* Cada sección define su acento + un fondo suave del mismo tono */
.sec-inicio   { --accent: #4a90d9; background: #f0f4ff; }  /* azul */
.sec-ayuda    { --accent: #e67e22; background: #fff8f0; }  /* naranja */
.sec-contacto { --accent: #27ae60; background: #f0fff4; }  /* verde */

/* El fondo cambia con la sección; el acento pinta navbar, títulos y bordes */
body    { transition: background .3s; }
.navbar { background: var(--accent); }
h1      { color: var(--accent); }
.panel  { border-left: 4px solid var(--accent); }

¿Qué es --accent?

--accent (acento, el color destacado de la sección) es una variable de CSS — se las llama custom properties. El nombre lo inventás vos, pero siempre empieza con dos guiones --. Sirve para guardar un valor (acá, un color) y reusarlo en muchos lugares sin repetirlo.

Se usa en dos pasos:

  • Definir el valor en cada sección → .sec-ayuda { --accent: #e67e22; }
  • Usarlo donde quieras ese color con var(--accent) → h1 { color: var(--accent); }
DEFINIR (1 vez).sec-ayuda { --accent: naranja }
→
USAR (las que quieras)navbar, títulos y bordes con var(--accent)

La ventaja: el color de cada sección queda definido en un solo lugar. Si mañana querés que "ayuda" sea roja, cambiás una línea (el --accent) y se actualizan de una el navbar, los títulos y los bordes que usan var(--accent). Y como cada sección define su propio --accent, el mismo var(--accent) pinta distinto según la sección activa.

Pensalo como una cajita con etiqueta: cada sección guarda su color en la cajita --accent; el resto del CSS no pregunta "¿qué color?", solo dice "usá el de la cajita" con var(--accent).

¿Qué podés cambiar por sección?

  • Color de fondo (como el ejemplo de arriba).
  • Imagen de fondo — background-image distinta por sección.
  • Borde del panel activo en el menú.
  • Color del navbar o del botón de la sección activa.
  • Transiciones entre secciones.
Tip: el --accent conviene reservarlo para detalles (navbar, títulos, bordes) y dejar el fondo en un tono suave: un body pintado entero del color fuerte cansa la vista. Con transition: background .3s en el body, el cambio de sección se ve gradual.

8. Buenas prácticas

  • Editar → add → commit → push en ese orden. Nunca saltees pasos.
  • Mensajes de commit descriptivos — "arreglo bug" no sirve. "Corrijo redirección después del login" es mejor.
  • Commit chicos, commit seguido. Un commit por cambio lógico. No esperes a tener todo el proyecto listo.
  • Mirá siempre git status antes de commitear para saber qué vas a incluir.
  • Siempre break al final de cada case, salvo que quieras fall-through a propósito.
  • default siempre por si alguien escribe una URL inválida.
  • Switch solo asigna variables. El HTML se escribe abajo, separado.
