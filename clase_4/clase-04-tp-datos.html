Trabajo práctico · Clase 4

Arrays asociativos y datos en archivo aparte

Guardás cada sección como un array asociativo, movés todos los datos a datos.php y hacés que el menú se arme solo con foreach. La página queda casi igual por fuera; cambia cómo están guardados los datos por dentro. Subís el avance como un nuevo commit.

Materia: Proyecto, Diseño e Implementación de Sistemas Computacionales · 7.º año

Objetivo

Partir de tu info.php de Clase 3 (el del switch) y dar un paso más: cada sección pasa a ser un array asociativo (un registro), todas las secciones viven juntas en un archivo aparte (datos.php), info.php queda corto y el menú se arma solo con un foreach. Es el puente hacia la base de datos que vamos a usar en la Clase 5.

Antes de empezar — repaso
Si algo de esto te cuesta, abrí el material de repaso de fundamentos (variables, if/switch, for/while/foreach). Recordá: = asigna, == compara; foreach recorre cada elemento de un array.

Consigna

Parte 1 — Una sección como array asociativo

  1. Elegí una sección (ej. ayuda) y, dentro de su case, juntá las cuatro variables en un solo array: 
    $seccion = [
    'titulo' => 'Ayuda',
    'texto'  => 'Instrucciones del sistema.',
    'imagen' => 'https://picsum.photos/seed/ayuda/800/350',
    'clase'  => 'sec-ayuda',
];
  2. En el HTML, cambiá <?= $titulo ?> por <?= $seccion['titulo'] ?> (y lo mismo con texto e imagen).
  3. Probá en el navegador: la sección tiene que verse igual que antes.
  4. Cuando una ande, repetí con las demás secciones.
✓ Checkpoint Parte 1
¿podés leer el título con $seccion['titulo']? ¿La página se ve igual que en Clase 3? Cuidado con dejar un <?= $titulo ?> viejo: si quedó, sale vacío.

Parte 2 — Datos en archivo aparte (datos.php)

  1. Creá un archivo nuevo, datos.php, que devuelva (con return) un array de arrays con todas tus secciones. La clave de afuera es lo que va en la URL (?seccion=): 
    <?php
return [
    'inicio' => ['titulo' => 'Inicio', 'texto' => '...', 'imagen' => '...', 'clase' => 'sec-inicio'],
    'ayuda'  => ['titulo' => 'Ayuda',  'texto' => '...', 'imagen' => '...', 'clase' => 'sec-ayuda'],
    'error'  => ['titulo' => 'No encontrada', 'texto' => '...', 'imagen' => '...', 'clase' => 'sec-error'],
];
  2. En info.php, traé esos datos: 
    $secciones = require 'datos.php';
  3. Mínimo 4 secciones + la de error.
✓ Checkpoint Parte 2
¿datos.php empieza con <?php y tiene return [ ... ];? Si te llega vacío, casi seguro te falta el return.

Parte 3 — Buscar la sección (lookup) y borrar el switch

  1. Reemplazá el switch por una búsqueda por clave: 
    $seccion = $_GET['seccion'] ?? 'inicio';
$datos   = $secciones[$seccion] ?? $secciones['error'];
  2. Antes del include de la cabecera, pasale los datos que esta necesita: 
    $titulo = $datos['titulo'];
$clase  = $datos['clase'];
  3. En el HTML usá <?= $datos['texto'] ?> y <?= $datos['imagen'] ?>.
  4. Probá ?seccion=ayuda y una inexistente (?seccion=admin): tiene que caer en error, no romperse.
✓ Checkpoint Parte 3
el switch ya no está. ?seccion=admin muestra la sección de error (gracias al ??). La cabecera no salió vacía (asignaste $titulo y $clase desde $datos).

Parte 4 — El menú que se arma solo (foreach)

  1. En cabecera.php (donde está el navbar), reemplazá los links escritos a mano por un foreach sobre $secciones: 
    <?php
  foreach ($secciones as $clave => $info) {
      if ($clave === 'error') continue;   // la de error no va en el menú
      echo "<a href='info.php?seccion=$clave'>" . $info['titulo'] . "</a>";
  }
?>
  2. Probalo: agregá una sección nueva a datos.php y recargá. Tiene que aparecer sola en el menú, sin tocar cabecera.php ni info.php.
✓ Checkpoint Parte 4
agregás una sección a datos.php → aparece sola en el menú. Ese es el sentido de separar los datos: tocás un solo archivo.

Parte 5 — Nuevo commit (subí el avance)

Ya tenés el repo de Clase 3. Ahora subís el avance de hoy como un nuevo commit:

  1. Guardá todos los cambios (incluido el archivo nuevo datos.php).
  2. En la terminal (Git Bash en VS Code: Ctrl + ñ): 
    git add .
git commit -m "Datos en datos.php, arrays asociativos y navbar con foreach"
git push
  3. Entrá a tu repo en GitHub: tiene que aparecer el archivo nuevo datos.php y un commit más. Es tu tercer o cuarto commit (según si hiciste el de tarea de Clase 3).
Opcional — techo
en el navbar, marcá con un color distinto la sección activa. Pista: dentro del foreach, compará $clave con $seccion y, si coinciden, agregá una clase al link.

Mantené lo de antes (no se borra)

  • session_start() y la protección de la página (login).
  • Los include 'includes/cabecera.php' / pie.php.
  • El CSS dinámico por sección (class="<?= $clase ?>" en el <body>).

Errores comunes

ErrorQué revisar
datos.php llega vacío¿Le pusiste return antes del array? Sin return, require no trae nada.
La cabecera sale vacía (sin título)¿Asignaste $titulo = $datos['titulo']; y $clase = $datos['clase']; antes del include?
Una sección sale vacíaQuedó un <?= $titulo ?> viejo en el HTML; ahora va <?= $datos['titulo'] ?>.
El menú no muestra nada¿El foreach recorre $secciones? ¿$secciones está cargado antes del include de la cabecera?
Una URL inexistente rompe la páginaFalta el ?? $secciones['error'] en el lookup.
GitHub no acepta la contraseñaNo va la clave de tu cuenta: va el token o gh auth login con GitHub CLI.

Para pensar (tarea de cierre)

Si cada array es una fila y las claves son las columnas, datos.php es casi una tabla. Para cada entidad de tu proyecto (usuarios, productos, turnos…), anotá qué campos tendría, como las claves de un array. Por ejemplo: usuario → nombre, email, clave. Eso lo usamos en la Clase 5 para armar la base de datos de verdad.
