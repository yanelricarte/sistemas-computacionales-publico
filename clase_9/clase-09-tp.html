Trabajo práctico · Clase 9

Modificá y borrá desde tu web: el CRUD completo

Tu sitio ya lista y agrega filas. En este TP le sumás las dos operaciones que faltan: corregir una fila cargada y eliminarla, con confirmación y sobre las dos tablas de tu base. Todo pasa por lo mismo: decir cuál fila con su id, y que ese id llegue al WHERE.

Materia: Proyecto, Diseño e Implementación de Sistemas Computacionales · 7.º año
Entorno: XAMPP (Apache + MySQL) · phpMyAdmin en http://localhost/phpmyadmin · tu sitio corre en http://localhost/...
Tiempo en clase: Partes 1 y 2 en el primer módulo · Parte 3 en el segundo · Parte 4 en el tercero · Partes 5, 6 y 7 en el cuarto · Parte 8, opcional, si terminás antes

Objetivo

Que tu sistema pase de agregar y listar a administrar sus datos. Al terminar, desde el navegador vas a poder corregir cualquier fila de tus dos tablas y borrarla —con una confirmación en el medio—, con el WHERE siempre presente y el dato entregado por sentencia preparada.

Las películas son un ejemplo
El TP usa la cartelera (peliculas + directores) para explicar, pero hacelo con tu proyecto: turnos + pacientes, productos + categorias, lo que sea. Lo evaluable es que la web modifique y borre filas de tu base.
Antes de empezar
XAMPP con Apache y MySQL encendidos, tu conexion.php funcionando y el listado del sitio mostrando las filas de tu base (Clase 8). El repaso de la Clase 8 —los archivos, las tres reglas y el código que ya escribiste— está en la §0 de la teoría de hoy.

Consigna

Parte 1 — Verificá tu punto de partida

Sin la Clase 8 cerrada no hay nada que editar. Esto se comprueba primero.

  1. Levantá XAMPP (Apache + MySQL) y abrí el listado de tu sitio: tiene que mostrar las filas de tu base.
  2. Agregá una fila con tu formulario y verificá que aparece en el listado.
  3. Entrá a tu repositorio en GitHub y confirmá que conexion.php no está subido.
  4. Anotá en tu carpeta el nombre exacto de tus dos tablas, de la columna id de cada una y de la columna que hace de clave foránea. Todo el TP se resuelve reemplazando esos nombres.
Si algo de la Clase 8 no está
Es el momento de resolverlo, no dentro de una hora. Si perdiste la base, importá tu .sql desde el repositorio (phpMyAdmin → Importar). Si te falta conexion.php, rehacelo con la plantilla que quedó en tu documentacion.md. Avisá si no lo podés recuperar.
✓ Checkpoint Parte 1
El listado muestra tu base, el formulario agrega, conexion.php no está en GitHub y tenés los nombres anotados.

Parte 2 — El id en el listado y la ficha de detalle

El id de cada fila ya lo tenés: el SELECT * del listado lo trae. Ahora lo vas a usar para abrir una fila.

  1. En el while de tu listado, agregá dos enlaces por fila: 
    <a href="ficha.php?id=<?php echo $fila['id']; ?>">Ver</a>
<a href="editar.php?id=<?php echo $fila['id']; ?>">Editar</a>
    Pasá el mouse por encima de dos filas distintas: los números de la barra de estado tienen que ser distintos.
  2. Creá ficha.php. Trae una fila, la de ese id, con sentencia preparada: 
    <?php
require 'conexion.php';

$id = $_GET['id'];

$stmt = mysqli_prepare($conexion, 'SELECT * FROM peliculas WHERE id = ?');
mysqli_stmt_bind_param($stmt, 'i', $id);
mysqli_stmt_execute($stmt);
$resultado = mysqli_stmt_get_result($stmt);
$pelicula  = mysqli_fetch_assoc($resultado);

if (!$pelicula) {
    die('No existe esa película.');
}
?>
<h1><?php echo $pelicula['titulo']; ?></h1>
<p>Año: <?php echo $pelicula['anio']; ?></p>
<p><a href="cartelera.php">← Volver al listado</a></p>
    (cambiá peliculas, titulo y anio por los de tu tabla).
  3. Abrí la ficha desde el listado: dos filas distintas tienen que mostrar datos distintos.
  4. Probá un id que no exista: escribí ficha.php?id=999 en la barra de direcciones. Tenés que ver tu mensaje, no un error de PHP. Anotá en la carpeta qué pasaría sin el if.
Esta consulta se usa tres veces hoy
El SELECT … WHERE id = ? de la ficha es exactamente el que va a usar el formulario de edición (Parte 3) y la página de confirmación del borrado (Parte 5). Dejalo funcionando bien acá y las dos partes siguientes son copiar y adaptar.
✓ Checkpoint Parte 2
Cada fila del listado abre su propia ficha, y un id inexistente responde con tu mensaje.

Parte 3 — El formulario precargado

Ahora la misma fila, pero dentro de los campos de un formulario. Es el cambio de <h1> a value.

  1. Creá editar.php copiando la consulta de la ficha, y armá el formulario: 
    <form method="POST" action="procesar_edicion.php">
  <input type="hidden" name="id" value="<?php echo $pelicula['id']; ?>">

  <label>Título:
    <input type="text" name="titulo"
           value="<?php echo htmlspecialchars($pelicula['titulo']); ?>" required>
  </label>

  <label>Año:
    <input type="number" name="anio" value="<?php echo $pelicula['anio']; ?>">
  </label>

  <button>Guardar cambios</button>
</form>
    El hidden no es opcional: es cómo el id llega al procesador.
  2. Agregá el desplegable de tu clave foránea, con la opción de esta fila marcada: 
    <label>Director:
  <select name="director_id">
    <?php
    $directores = mysqli_query($conexion, 'SELECT id, nombre FROM directores ORDER BY nombre');
    while ($d = mysqli_fetch_assoc($directores)) {
    ?>
      <option value="<?php echo $d['id']; ?>"
        <?php if ($d['id'] == $pelicula['director_id']) { echo 'selected'; } ?>>
        <?php echo $d['nombre']; ?>
      </option>
    <?php } ?>
  </select>
</label>
  3. Probalo con dos filas que tengan distinto valor de FK. Cada una tiene que abrir con su propio director en el menú. Si las dos abren en el mismo, revisá la comparación: es ==, no =.
  4. Probá abrir editar.php sin el ?id= (escribiendo solo el nombre del archivo). Anotá el error que aparece y de dónde viene.
Por qué el htmlspecialchars
Cargá una fila cuyo texto tenga una comilla doble —El "Zorro"— y mirá el campo. Sin htmlspecialchars, la comilla cierra el value=" y el campo aparece cortado. Es el hermano del apóstrofo que rompía el INSERT en la Clase 8.
✓ Checkpoint Parte 3
editar.php?id=… abre con los datos de esa fila en los campos y con el desplegable marcado en el valor que tiene la fila. Todavía no guarda nada.

Parte 4 — Guardá los cambios con UPDATE

  1. Creá procesar_edicion.php: 
    <?php
require 'conexion.php';

$id          = $_POST['id'];
$titulo      = $_POST['titulo'];
$anio        = $_POST['anio'];
$director_id = $_POST['director_id'];

$stmt = mysqli_prepare($conexion,
    'UPDATE peliculas SET titulo = ?, anio = ?, director_id = ? WHERE id = ?');
mysqli_stmt_bind_param($stmt, 'siii', $titulo, $anio, $director_id, $id);
mysqli_stmt_execute($stmt);

header('Location: cartelera.php?ok=guardado');
?>
    El $id va último: es el ? del WHERE. Y 'siii' lleva una letra por cada ?, en ese orden.
  2. Corregí un dato desde la web y verificalo en phpMyAdmin: la fila cambió, y solo esa.
  3. La prueba del WHERE, sobre una copia. En phpMyAdmin, con tu tabla seleccionada:
    1. Operaciones → Copiar tabla a…, nombre prueba_borrar, opción estructura y datos.
    2. Pestaña SQL: UPDATE prueba_borrar SET anio = 1900; — sin WHERE.
    3. Leé el número de filas afectadas y corré un SELECT sobre la copia. Anotá lo que ves.
    4. DROP TABLE prueba_borrar;
    Nunca sobre la tabla de tu proyecto: sin WHERE la operación no falla, y no hay botón de deshacer.
  4. Agregá el aviso al usuario. Arriba de tu listado: 
    <?php
$aviso = $_GET['ok'] ?? '';

if ($aviso === 'guardado') { echo '<p class="aviso">Los cambios se guardaron.</p>'; }
if ($aviso === 'borrado')  { echo '<p class="aviso">La fila se borró.</p>'; }
?>
    Y una regla mínima en tu estilos.css para que se vea: 
    .aviso {
  background: #e8f5e9;
  border-left: 4px solid #43a047;
  padding: 10px 14px;
  margin: 16px 0;
}
✓ Checkpoint Parte 4
Corregís un dato desde la web, el cambio se ve en phpMyAdmin y al volver al listado aparece el aviso.

Parte 5 — Borrar con confirmación

Borrar va en dos pasos: una página que pregunta (llega por GET) y un procesador que borra (llega por POST).

  1. En el listado, agregá el enlace de borrado en cada fila: 
    <a href="borrar.php?id=<?php echo $fila['id']; ?>">Borrar</a>
  2. Creá borrar.php: la misma consulta de la ficha, y en vez de mostrar la fila, preguntá por ella. 
    <p>¿Borrar <strong><?php echo htmlspecialchars($pelicula['titulo']); ?></strong>?
   Esta acción no se puede deshacer.</p>

<form method="POST" action="procesar_borrado.php">
  <input type="hidden" name="id" value="<?php echo $pelicula['id']; ?>">
  <button>Sí, borrar</button>
</form>
<p><a href="cartelera.php">Cancelar</a></p>
    La confirmación tiene que nombrar lo que se va a borrar.
  3. Creá procesar_borrado.php: 
    <?php
require 'conexion.php';

$id = $_POST['id'];

$stmt = mysqli_prepare($conexion, 'DELETE FROM peliculas WHERE id = ?');
mysqli_stmt_bind_param($stmt, 'i', $id);
mysqli_stmt_execute($stmt);

header('Location: cartelera.php?ok=borrado');
?>
  4. Cargá una fila de prueba, borrala pasando por la confirmación, y comprobá que desapareció del listado y de phpMyAdmin. Probá también el Cancelar: tiene que volver sin borrar nada.
✓ Checkpoint Parte 5
El borrado pide confirmación nombrando la fila, borra al aceptar y no hace nada al cancelar.

Parte 6 — El mismo patrón en tu segunda tabla

La otra entidad —la del lado del uno, la que apunta tu clave foránea— es más simple: no tiene FK, así que su formulario de edición no lleva desplegable. Es el mismo patrón con una pieza menos.

  1. Si no lo tenés, hacé el listado de esa tabla (el SELECT de la Clase 8 sobre la otra tabla), con sus enlaces de editar y borrar.
  2. Copiá el patrón: editar_director.php + procesar_edicion_director.php, y borrar_director.php + procesar_borrado_director.php.
  3. Corregí un nombre desde la web y verificalo en phpMyAdmin.
  4. Probá borrar una fila que tenga hijas (un director con películas cargadas). Anotá el error que aparece.
  5. Hacé que el sistema lo explique en vez de mostrar el error de PHP: 
    <?php
if (mysqli_stmt_execute($stmt)) {
    header('Location: directores.php?ok=borrado');
} else {
    header('Location: directores.php?error=tiene_peliculas');
}
?>
    Y en el listado de esa tabla, el aviso correspondiente: 
    <?php
$error = $_GET['error'] ?? '';
if ($error === 'tiene_peliculas') {
    echo '<p class="aviso">No se puede borrar: tiene películas cargadas.</p>';
}
?>
1451 y 1452 son la misma garantía
En la Clase 7 la base impidió cargar una película que apuntaba a un director inexistente (1452). Ahora impide borrar un director que dejaría películas apuntando al vacío (1451). Se llama integridad referencial, y que la base te frene es lo correcto: lo que falta siempre es que el sistema lo explique.
✓ Checkpoint Parte 6
Las dos tablas se pueden editar y borrar desde el sitio, y el borrado de una fila apuntada muestra un aviso en vez de un error.

Parte 8 (opcional) — Si terminaste antes

Estas dos no son obligatorias ni entran en la evaluación, y conviene hacerlas en este orden. Las dos siguen sobre tu mismo proyecto.

A — Comprobá en el servidor

El required del formulario lo controla el navegador, y el navegador está del otro lado: se puede saltear mandando el POST sin pasar por tu página. La comprobación que vale es la que hace el servidor.

  1. En el procesador de la edición, después de leer los datos del POST y antes de la consulta: 
    <?php
$titulo = trim($_POST['titulo']);

if ($titulo === '') {
    header('Location: editar.php?id=' . $id . '&error=vacio');
    exit;
}
  2. Y en editar.php, arriba del formulario, el aviso: 
    <?php
if (($_GET['error'] ?? '') === 'vacio') {
    echo '<p class="aviso">El título no puede quedar vacío.</p>';
}
?>
  3. Probalo: borrá el contenido del campo, quitale el required al input a mano y mandá el formulario. Tiene que volver con el aviso y sin haber tocado la fila.
El exit no es opcional
El header le habla al navegador y no interrumpe el PHP: sin el exit;, el programa sigue con las líneas de abajo y ejecuta el UPDATE igual. Es un error que no da ningún mensaje — la fila se guarda con el título vacío y el aviso aparece como si se hubiera evitado. En los procesadores de las partes anteriores no hizo falta porque la redirección era la última línea del archivo; acá, con código debajo, es obligatorio.

B — El nombre en vez del número: el JOIN

Tu listado muestra el director_id, que es un número. Ese fue el límite que quedó anunciado en la Clase 8: para mostrar el nombre hay que traer datos de las dos tablas en una sola consulta.

  1. Corré primero la consulta en phpMyAdmin, así el error de SQL se ve donde se ve: 
    SELECT peliculas.titulo, peliculas.anio, directores.nombre
  FROM peliculas
  JOIN directores ON peliculas.director_id = directores.id
 ORDER BY peliculas.titulo
  2. El ON dice cómo se emparejan las filas: la clave foránea de una tabla con la clave primaria de la otra. Es la relación que armaste en la Clase 7, escrita como consulta.
  3. Llevala al listado de tu sitio. En PHP no cambia nada —el mismo mysqli_query y el mismo while—, solo que ahora $fila['nombre'] existe y podés mostrarlo en lugar del número.
Cuando las dos tablas tienen columnas con el mismo nombre
Las dos tienen id, así que en la consulta se escribe la tabla adelante: peliculas.id, directores.id. Con una sola tabla no hacía falta; con dos, sí.
