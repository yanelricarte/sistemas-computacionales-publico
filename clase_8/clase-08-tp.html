Trabajo práctico · Clase 8

Conectá tu web con la base: mostrar y agregar datos

Tu sitio deja de leer datos.php (un array escrito a mano) y empieza a leer la base real (mostrar) y a agregarle filas (insertar) desde un formulario, respetando la clave foránea y sin subir los datos de acceso al repositorio. Es el inicio de la Etapa 3: PHP y MySQL conectados.

Materia: Proyecto, Diseño e Implementación de Sistemas Computacionales · 7.º año
Entorno: XAMPP (Apache + MySQL) · phpMyAdmin en http://localhost/phpmyadmin · tu sitio corre en http://localhost/...
Tiempo en clase: Parte 1 en el primer módulo · Partes 2 y 3 en el segundo y tercero · Partes 4 y 5 en el cuarto

Objetivo

Conectar la web de tu proyecto con su base de datos real. Que el listado del sitio lea las filas que cargaste en la Clase 7, y que un formulario las agregue desde el navegador — siempre por la clave foránea y con el INSERT protegido. Con esto dejás atrás el array escrito a mano (datos.php) y tu web pasa a tener datos vivos.

Las películas son un ejemplo
Todo el TP usa la cartelera (peliculas + directores) para explicar, pero hacelo con tu proyecto: turnos + pacientes, productos + categorias, lo que sea. Lo evaluable es que la web lea y escriba en tu base real.
Antes de empezar
XAMPP con Apache y MySQL encendidos, tu base de la Clase 7 respondiendo (dos tablas, FK declarada) y los 4 datos de acceso a tu MySQL local anotados. Quien haya perdido la base, la reimporta desde su .sql del repositorio. Repaso de conceptos en la teoría de Clase 8.

Consigna

Parte 1 — Verificá tu punto de partida

Esta clase arranca confirmando que todos están en el mismo lugar. Sin la base de la Clase 7 respondiendo, el resto no funciona.

  1. Levantá XAMPP (Apache + MySQL) y entrá a http://localhost/phpmyadmin.
  2. Abrí tu base y corré SELECT * FROM cada una de tus dos tablas. Tienen que devolver filas.
  3. Verificá que la relación esté declarada: tabla que apunta → pestaña Estructura → Vista de relaciones → tu FK figura ahí.
  4. Escribí en tu carpeta los 4 datos de acceso a tu base: host, usuario, contraseña y el nombre de tu base.
✓ Checkpoint Parte 1
Las dos tablas responden a un SELECT y tenés los 4 datos anotados. Sin esto, el resto de la clase no arranca — avisá antes de seguir.

Parte 2 — Conectá PHP con tu base

Vas a crear el archivo conexion.php: los 4 datos de tu base y la apertura del canal. Se escribe una sola vez y se reutiliza en todas las páginas que toquen datos.

  1. Creá el archivo conexion.php en la raíz de tu proyecto, con tus 4 datos: 
    <?php
// los 4 datos de TU base
$host      = 'localhost';
$usuario   = 'root';
$clave     = '';
$base      = 'cartelera';          // cambiá por el nombre de la tuya

$conexion = mysqli_connect($host, $usuario, $clave, $base);
if (!$conexion) {
    die('Error de conexión: ' . mysqli_connect_error());
}
?>
  2. Creá una página de prueba probar_conexion.php que incluya la conexión: 
    <?php require 'conexion.php'; ?>
<p>Conectado a la base <?php echo $base; ?>.</p>
    Abrila en el navegador: tenés que ver "Conectado a la base …".
  3. Probalo fallando a propósito (para conocer el mensaje de error): apagá MySQL en XAMPP y recargá la página; anotá el error que aparece. Después volvé a encenderlo.
  4. Creá el archivo .gitignore en la raíz de tu proyecto: 
    conexion.php
    conexion.php no se sube: tiene la llave de tu base. Su plantilla la vas a documentar en la Parte 5 para poder recrearla en otra computadora.
La llave nunca se publica
Un repositorio en GitHub es visible para quien tenga el enlace, y lo que se sube queda ahí aunque después se borre. El archivo con los datos de acceso (conexion.php) no se sube nunca: por eso existe el .gitignore. Si lo subís una vez, se considera comprometido.
✓ Checkpoint Parte 2
El navegador dice "Conectado a la base" y conexion.php figura en tu .gitignore.

Parte 3 — Mostrá los datos de tu base en la web

Vas a reemplazar la cartelera de datos.php por la base real. Compará y notá que el resto del listado no cambia: las filas son los mismos arrays de la Clase 4, solo que ahora las entrega MySQL.

  1. Abrí la página de tu sitio que hoy muestra la cartelera (la que lee datos.php).
  2. Arriba de todo, agregá: <?php require 'conexion.php'; ?>
  3. Reemplazá la lectura del array por la consulta a tu base: 
    <?php
$resultado = mysqli_query($conexion, 'SELECT * FROM peliculas');
while ($fila = mysqli_fetch_assoc($resultado)) {
?>
  <article>
    <h2><?php echo $fila['titulo']; ?></h2>
    <p><?php echo $fila['anio']; ?></p>
  </article>
<?php } ?>

    Cambiá peliculas, titulo y anio por los nombres de tu tabla. Las claves de $fila son las columnas de tu CREATE TABLE.

  4. Actualizá la página en el navegador. El listado tiene que mostrar las filas de tu base.
  5. Comprobación de que es la base real: en phpMyAdmin agregá una fila a tu tabla, actualizá la página y la fila nueva tiene que aparecer.
✓ Checkpoint Parte 3
El listado del sitio muestra los datos de la base real: si los cambiás en phpMyAdmin, cambian en la web.

Parte 4 — Agregá filas desde un formulario

Ahora la web no solo lee: escribe. El formulario manda por POST, y el procesador guarda la fila con una sentencia preparada. Y hay una regla que no se negocia.

El dato del usuario nunca va dentro de la consulta
Pegar el dato del formulario entre comillas en el SQL — 'INSERT ... VALUES ("' . $_POST['titulo'] . '")' — es un error: un apóstrofo en el título rompe la consulta, y lo peor, quien escribe podría escribir SQL en vez de un título. Ese ataque se llama inyección SQL. Se previene con una sola práctica, desde el principio: la sentencia preparada.
  1. Creá el formulario de alta (podés reusar el de la Clase 1). El menú del director se llena desde la base — muestra nombres, envía ids: 
    <form method="POST" action="procesar_pelicula.php">
  <label>Título: <input type="text" name="titulo" required></label>
  <label>Año: <input type="number" name="anio"></label>
  <label>Director:
    <select name="director_id">
      <?php
      $resultado = mysqli_query($conexion,
          'SELECT id, nombre FROM directores ORDER BY nombre');
      while ($d = mysqli_fetch_assoc($resultado)) {
      ?>
        <option value="<?php echo $d['id']; ?>">
          <?php echo $d['nombre']; ?>
        </option>
      <?php } ?>
    </select>
  </label>
  <button>Guardar</button>
</form>
  2. Creá el procesador. Los ? son lugares reservados: la consulta se prepara con ellos y el dato se entrega por separado, después. 
    <?php
require 'conexion.php';

$titulo      = $_POST['titulo'];
$anio        = $_POST['anio'];
$director_id = $_POST['director_id'];

$stmt = mysqli_prepare($conexion,
    'INSERT INTO peliculas (titulo, anio, director_id) VALUES (?, ?, ?)');
mysqli_stmt_bind_param($stmt, 'sii', $titulo, $anio, $director_id);
mysqli_stmt_execute($stmt);

header('Location: cartelera.php');
?>

    En 'sii' se describe cada lugar reservado: s = texto, i = entero. Adaptalo a las columnas de tu tabla.

  3. Cargá una fila por el formulario y verificá en el listado que aparece. Revisá la fila en phpMyAdmin: la FK trae el id del director, no su nombre.
  4. Probá qué pasa si la FK no existe: enviá un director_id inexistente (editalo en el formulario) y anotá el mensaje de error. Es la integridad referencial de la Clase 7, ahora llegando desde la web.
✓ Checkpoint Parte 4
La fila agregada por el formulario aparece en el listado y en phpMyAdmin, con su FK válida.

Parte 5 — Documentá y versioná

  1. Actualizá tu documentacion.md (el de la Clase 6):
    • El sitio ahora lee y escribe en la base: qué página muestra y cuál agrega.
    • La plantilla de conexion.php completa (los 4 datos con espacios para completar), para poder recrearla en otra computadora. Lo que se comparte es la plantilla, nunca la llave.
  2. Commit y push: 
    git add .    # o los archivos que tocaste: cartelera.php, procesar_pelicula.php, .gitignore, documentacion.md
git commit -m "Web conectada a MySQL: la cartelera lee y agrega filas"
git push
  3. Entrá a tu repositorio en GitHub desde el navegador y verificá que conexion.php no está subido.
✓ Checkpoint Parte 5
La plantilla está en documentacion.md, el avance está en el repo y conexion.php no aparece en GitHub.

Errores comunes

ErrorQué revisar
mysqli_connect() no existe / "undefined function"Faltó el <?php require 'conexion.php'; ?> en la página, o la página guardada sin extensión .php.
Error de conexión (no conecta)Leer mysqli_connect_error(): MySQL apagado, nombre de base mal escrito o credenciales equivocadas.
mysqli_fetch_assoc() espera 1 parámetro$resultado no vino de mysqli_query: se llamó fetch_assoc sobre algo que no es un resultado.
Undefined array key "titulo"La clave no coincide con la columna real: las claves de $fila son los nombres del CREATE TABLE.
Error de sintaxis SQL en el INSERTSe concatenó el dato del usuario dentro de la consulta (un apóstrofo la rompió). Usar la sentencia preparada.
mysqli_stmt_execute() falla con FKEl director_id no existe en la tabla apuntada (error 1452). Correr un SELECT y elegir un id real del menú.
conexion.php aparece en GitHubNo se creó el .gitignore, o se hizo git add antes de crearlo. Verificarlo antes del push.
La página muestra el código PHP en vez de ejecutarloApache no está procesando el PHP: archivo fuera de htdocs o con extensión equivocada. Abrir desde http://localhost/....

Para pensar (tarea de cierre)

Hoy la web lee y agrega filas. Cuando una fila ya cargada tenga un dato mal (un título con una falta, un año equivocado), la web debería poder modificarla — y también borrarla. Esas dos operaciones completan el CRUD (crear, leer, actualizar, borrar) que se empezó hoy. La próxima clase las hace desde el sitio.

  1. Dejá el avance en el repositorio: la web lee y escribe en tu base, con conexion.php protegido por el .gitignore.
  2. Actualizá el documentacion.md con qué página muestra, cuál agrega, y la plantilla de conexion.php.
  3. Pensá: para que la web pueda modificar una fila, el formulario tendría que aparecer ya cargado con los datos de esa fila. ¿Cómo llegaría el id de la fila a elegir al formulario de edición?
